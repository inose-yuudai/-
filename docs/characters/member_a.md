# member_a — 実在の人物を元にしたキャラクター

写真の人物を、ゲーム内の主人公たちと同じ画風の 3D キャラクターにする。Tripo で生成し、リグとモーションも Tripo で付ける。

- 生成の設定: [`tools/tripo/characters/member_a.json`](../../tools/tripo/characters/member_a.json)
- 実行手順: [`tools/tripo/README.md`](../../tools/tripo/README.md)

> 写真は Tripo と、Tripo が使う画像生成モデルの提供元に送られる。本人以外の写真なら、使う前に本人の了承を取ること。

---

## 1. 画風: どちらの参考に合わせるか

渡された 2 枚の参考は**等身が違う**ので、両方に「合わせる」ことはできない。

| | 1 枚目（主人公「あなた」） | 2 枚目（ほかのキャラ） |
|---|---|---|
| 等身 | 5〜6 頭身 | 2〜2.5 頭身（ちびキャラ） |
| 共通点 | 単色の塗り、形を大きくまとめた造形、細かい質感なし | 同左 |

**推奨は 1 枚目（設定の `"proportion": "hero"`）。**

1. **モーションを多く付けたいなら、普通の人体の比率に近いほうが壊れにくい。** 自動リグや既製のモーションは、普通の人体の比率を前提に作られている。2.5 頭身だと腕が短く頭が大きいので、手が顔に届かずにめり込む、走ると腕が頭を突き抜ける、といった崩れが出る。ダブルピースのように顔の近くで手を使う動きは、ちびだとほぼ手付けになる。
2. **主人公と同じ画面に並ぶなら、等身はそろえる。** 等身の違うキャラが同じ画面に並ぶと、ちぐはぐに見える。

ちびにする利点もある。顔が大きくなるので、似顔絵として特徴が伝わりやすい。会話シーンやマスコット用ならちびのほうがよい。`--proportion chibi` で立ち絵だけ作って見比べられる（立ち絵 1 枚分のクレジットで済む）。

## 2. 写真から何を残し、何を捨てるか

3D の顔は数百ポリゴンしかなく、細かいところは再現できない。**遠目のシルエットでその人だと分かるもの**を残し、ほかは捨てる。

| 要素 | 判断 | 理由 |
|---|---|---|
| 黒髪のマッシュ（ぱっつん前髪） | **残す。少し大げさに** | いちばん目立つ特徴。シルエットだけで判別できる |
| 丸眼鏡 | **残す。フレームは太く単純に** | 細いフレームは AI の 3D 生成でつぶれる。太くすれば画風にも合う |
| 笑顔（目が細くなる） | 残す | 3 枚とも笑っている。この人らしさになる |
| マスク | **捨てる** | 顔を隠すと、顔の特徴が伝わらなくなる |
| 名札・ストラップ | 捨てる | 細く垂れ下がる物はリグで崩れる |
| 手に持った物（トロフィー・看板） | **捨てる** | 手と一体のメッシュになり、指のリグが壊れる。小道具は Unity 側で別オブジェクトとして手に持たせる |

**基本の服装は 5 枚目（白 T シャツ・ベージュのチノパン・黒スニーカー）。** 全身が写っていて形も単純なので、AI での生成が安定しやすい。

着せ替えの候補（企画）:
- えんじ色のパーカー（4 枚目）: スタッフ・裏方風の衣装
- 黒ジャケット＋グレーのパーカー（3 枚目）: 外出着

## 3. 写真を直接 Tripo に入れない理由

写真をそのまま image_to_model に入れると、次のことが起きる。

- 写実寄りの顔と体になり、画風が合わない
- 手に持ったトロフィーや、体にくっついた腕が一つのメッシュになり、リグが入らないか、入っても崩れる
- 背景の椅子や看板も形として拾われる

そこで次の順番で作る。

```
参考画像 5 枚 ──generate_image──▶ 立ち絵（A ポーズ・白背景・この画風）   ← 目で確認①
立ち絵       ──generate_multiview_image──▶ 前・左・後・右の 4 枚            ← 目で確認②
4 枚         ──multiview_to_model──▶ 3D モデル                              ← 目で確認③
モデル       ──animate_prerigcheck → animate_rig（Mixamo 互換）──▶ リグ付き FBX
リグ         ──animate_retarget──▶ モーション FBX（1 モーション 1 ファイル）
```

確認①でこけるのがいちばん安い。**似ていない立ち絵のまま 3D に進まない。**

## 4. モーション

### Tripo のプリセット（自動で付く）

| プリセット | ゲームでの用途 |
|---|---|
| `preset:idle` | 待機（行動選択中） |
| `preset:walk` / `preset:run` | 移動 |
| `preset:jump` | ジャンプ・回避 |
| `preset:slash` | 通常攻撃 |
| `preset:hurt` | 被ダメージ |
| `preset:fall` | 戦闘不能 |
| `preset:turn` | 振り向き |

ほかに `dive` `climb` `shoot` がある。リグのバージョンによってはさらに多い。使えるプリセット名は Tripo の API ドキュメントで確認して、設定の `animations` に足す。

### この人だけのモーション（企画）

プリセットは誰に付けても同じ動きになる。**キャラの個性はエモートで出す。** 写真にちょうどよい素材がある。

| エモート | 元の写真 | 使う場面 |
|---|---|---|
| ダブルピース | 3 枚目 | 勝利・リアクション |
| トロフィーを掲げる | 5 枚目 | MVP・1 位の演出 |
| 看板を胸の前に持つ | 4 枚目 | 待機中の放置モーション、ロビー |

これらは Tripo のプリセットにはないので、次のどちらかで作る。

1. **Mixamo の既製モーションを流用する（おすすめ）。** リグを `spec: "mixamo"` で作り、Unity で Humanoid として取り込めば、Mixamo のモーション（Victory、Cheering など）をそのまま使える。Mixamo にこのモデルをアップロードする必要はない。モーションは Mixamo の標準キャラで「Without Skin」を選んでダウンロードすればよい。
2. **Unity で手付けする。** Humanoid のマッスル値を Animation ウィンドウでキーにする。
   - ピースの指: Tripo の自動リグに指のボーンが入るかどうかは、取り込んでみないと分からない。Avatar の設定で指のボーンが割り当てられているか確認する。ない場合は、ピースの手の形をした別メッシュに差し替える。

トロフィー・看板は手のボーンの子に付けた別オブジェクトにする。メッシュに含めない。

## 5. Unity への取り込み

| ファイル | 設定 |
|---|---|
| `rig/member_a.fbx`（体） | Rig → Animation Type: **Humanoid**、Avatar Definition: **Create From This Model**。Configure を開いて、ボーンの割り当てが緑になっていることを確認する |
| `anim/member_a@*.fbx`（モーション） | Rig → Humanoid、Avatar Definition: **Copy From Other Avatar** に体の Avatar を指定 |
| idle / walk / run | Animation → **Loop Time** をオン |
| walk / run | **Root Transform Position (XZ)** をどう扱うかを決める。キャラクターをスクリプトで動かすなら Bake Into Pose をオンにして、その場で足踏みさせる |
| 全モーション | Root Transform Rotation と Position (Y) は **Bake Into Pose** をオン（向きと高さがずれていくのを防ぐ） |

Animator の構成:

- **Base Layer**: Locomotion（Speed パラメータで idle → walk → run を切り替えるブレンドツリー）
- **Action**: Trigger で再生（攻撃 / 被ダメ / 戦闘不能 / エモート）

モーションを足すたびに遷移の矢印を手で引く作りにすると、すぐに管理できなくなる。エモートは `AnimatorOverrideController` でクリップだけ差し替えられるようにしておくと、キャラが増えても Animator Controller は 1 つで済む。
